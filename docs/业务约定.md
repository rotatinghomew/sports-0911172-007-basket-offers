# 当前业务约定

purchase 连接同次购买拆出的小票；gifts 单列赠品。成交时保存各商品实际单件金额，组合折扣按标价比例分配到商品并把分币余量留给编号排序的最后一件，售后沿用成交金额退款，不把退货当新购买。offers 为人工组合，redeem 会真实扣货并留下促销来源。

## 关联发现与检验（discovery）

分析输入为购买级净购物篮（`product/netbaskets.py`），不是小票：同一 purchase 的多张票合并为一个项集，支持度按购买计一次；赠品整行剔除；退货按净数量扣除，退净的商品不进项集；换货通过其退货单沿用同一处理。任一小票带 promotion 的购买整体归入促销流（含老捆绑核销、整单活动与组合试用），只有无 promotion 的购买进入自然流。全为赠品/退净的自然购买仍计入购买总数。

`discovery.run` 按可观察日期把自然购买切成发现样本与持出验证样本（cutoff 含当天，之后为持出），参与发现的购买不参与验证。对达到最小支持计数的商品对计算支持度、双向置信度、提升度、Fisher 双侧精确检验 p 值与 BH-FDR 调整值；稀少对（共现低于 `min_support`）不进入排名。结论三分类：

- `association`：FDR 显著、提升度达标、持出样本仍同向，且客群与赛程阶段各样本充足分层方向稳定；
- `promotion_induced`：自然流证据不足，但促销流共现达到独立门槛，共现更可能由促销诱导；
- `undetermined`：两条流都不足以判断。

分层样本数低于 `min_stratum_n` 记为证据薄弱（thin）而非方向不稳定。发现结论只描述历史关联，不构成“搭售会增收”的因果证据；默认客群按购买次数划分回头客/单次客，也可显式传 `segments`，赛程阶段由 `phases` 给定。

## 组合试用（trials）

`trial` 必须绑定一次 discovery 中的具体规则，商品集合即证据集合；只有 `association` 规则可开试用，替换商品或沿用旧证据都会被拒。`trials.attempt` 先做名额、库存、停用与互斥预检，失败写 `unfulfilled` 并附原因码（如 `out_of_stock:<sku>`、`capacity_exhausted`、`offer_exclusive`），不扣库存、不留半截事务。试用核销在 basket 与 redemption 上带 `trial` 字段，净购物篮将其归入促销流，因此试用自己促成的共现不会回流为下一次独立发现。`trials.report` 汇总净收入（成交额减折扣减退货）、退货、换货与未兑现，并给发现截止日前的自然流描述性基线，基线不证明增收。

## 数据与一致性

金额均为整数分；日期使用零补齐的日期或同一时区时间字符串，跨时区输入应由调用方先规范化。所有 ID 为业务编号。写入会增加修订并保留旧值，历史 `recorded_at` 是登记时间，不等于事实发生时间；不能据此推断未观测到的业务事实。

单次业务操作是一个事务，失败不留下中间结果；整份回放按顺序逐项执行，前一项成功不会因为后一项失败而撤销。现有重复编号拒绝语义及已完成状态的重试语义由业务操作维护。操作台 JSON 中 `results` 是操作结果，`state` 为当前业务记录；历史以 `Store.history` 查询，当前状态与历史不能混为一谈。
